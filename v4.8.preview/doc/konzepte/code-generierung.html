Codegenerierung

Im Repository von Framework Studio liegen keine vollständigen C#-Klassen, sondern Metadaten (Query, Properties, Relationen, Vererbung) und der Code, den Sie selbst schreiben. Beim Kompilieren erzeugt Framework Studio daraus C#-Code und übersetzt ihn in Assemblies (siehe Kompilierreihenfolge).

Den generierten Code sehen Sie im Repository nicht, Sie arbeiten aber ständig mit ihm: Jeder Aufruf von this.sNameValue, sNameOrgValue oder cdCompanyFactory.Create() greift auf generierte Member zu. Diese Seite zeigt am Beispiel einer Component aus dem Package FSDemo, was erzeugt wird und wie Sie es in eigenem Code verwenden.

Note

Die Klassensignatur einer Component ändern Sie über die Metadaten, nicht über Code. Neue Properties, eine geänderte Query oder eine Basis-Component führen beim nächsten Kompilieren automatisch zu passend generierten Membern.

Beispiel aus FSDemo

Die Component FS.Demo.Company.cdCompany aus dem Package FSDemo hat eine Query auf die Tabelle Company. Von ihren Properties werden hier diese betrachtet:

Property Property Type Datentyp Mapping
ROWID Generated FSSystemGuid Spalte Company.FSROWID, Primärschlüssel
sID Generated FSstring Spalte Company.ID
sName Generated FSstring Spalte Company.Name
sCountry Generated FSstring Spalte Company.Country
oCountry Relation Component FS.Demo.Country.cdCountry Depends On: sCountry → cdCountry.sID

Die folgenden Auszüge stammen aus dem generierten Code von cdCompany. Sie sind gekürzt, ausgelassen sind u. a. Kommentare, Markierungen für die IDE und Member, die hier keine Rolle spielen.

Die Klassen einer Component

Für cdCompany entstehen zwei Klassen und eine Factory:

// Code-Code: Properties, eigene Methoden und alle generierten Hilfs-Member
public partial class FSDemo_cdCompany
    : FS.Hosting.Shared.FrameworkDataObject<FS.Demo.Company.cdCompany_DataStruct, FS.Demo.Company.cdCompany_PKStruct>,
      FS.Demo.Company.FSDemo_IcdCompany, FS.Hosting.Shared.IObjectWithRowid
{
    …
}

// Use-Code: die Klasse, mit der Sie im Code arbeiten
public partial class cdCompany : FS.Demo.Company.FSDemo_cdCompany, FS.Demo.Company.IcdCompany
{
    public override System.Type GetFactoryType() { return typeof(FS.Demo.Company.cdCompanyFactory); }
    protected override void OnSaveAction() { … }
    public class QueryInfoClass : FS.Hosting.Shared.FrameworkQueryInfo { … }
    …
}
Klasse Inhalt
Use-Code (cdCompany) Die Klasse, die Sie im Code verwenden. Sie implementiert das Interface IcdCompany sowie die Interfaces, die an der Component unter Interfaces eingetragen sind. Bei einer Component mit Query enthält sie außerdem die generierte Speicherlogik OnSaveAction() und die QueryInfoClass.
Code-Code (FSDemo_cdCompany) Enthält die Properties mit ihrer Datenbank-Anbindung, Ihre Methoden und Konstruktoren und die Hilfs-Member, die pro Property generiert werden. Der Name setzt sich aus dem Assembly-Präfix des Packages und dem Namen der Component zusammen.
Factory (cdCompanyFactory) Wird zusammen mit dem Interface kompiliert und steht deshalb auch in anderen Namespaces zur Verfügung. cdCompanyFactory.Create() liefert eine neue Instanz, auch wenn nur das Interface bekannt ist (siehe UseInterface). Außerdem enthält die Factory den Metadatentyp mdt_<Name> aller Properties, die weder private noch internal sind, z. B. cdCompanyFactory.mdt_sName.

cdCompany hat eine Query, deshalb erbt die Code-Code-Klasse von FrameworkDataObject. Bei anderen Component-Typen ist die Basisklasse eine andere:

Component-Typ Basisklasse der Code-Code-Klasse
Component ohne Query FS.Hosting.Shared.DevFrameworkObject
Component mit Query (DataComponent) FS.Hosting.Shared.FrameworkDataObject<<Name>_DataStruct, <Name>_PKStruct>
Collection FS.Hosting.Shared.DevFrameworkObjectColl
Collection einer DataComponent FS.Hosting.Shared.FrameworkDataColl<…_DataStruct, …_PKStruct>
TextCollection FS.Hosting.Shared.MultiLanguage.DevFrameworkObjectTextColl
cGlobal FS.Hosting.Shared.GlobalObj.cGlobalBase
Component mit Basis-Component die Basis-Component

FrameworkDataObject und cGlobalBase erben von DevFrameworkObject, FrameworkDataColl und DevFrameworkObjectTextColl von DevFrameworkObjectColl. Gemeinsame Basis aller Components und Collections ist DevFrameworkBaseObject. Die Methoden, die Sie von dort erben (Load, Save, State, Entry-Points wie OnBeforeSave usw.), sind unter Registerkarte Methods beschrieben.

Ein Generated-Property mit Mapping

Für das Property sName erzeugt Framework Studio diesen Code:

// Der Wert hinter dem Property
protected FSstring sNameValue
{
    get
    {
        return this.GetMLText(FS.Demo.Company.cdCompanyFactory.mdt_sName, "sName", this._DBData.sName);
    }
    set
    {
        if (this.sNameValue == value || !this.CanSetPropertyDB()) return;
        if (!this.SetMLText(FS.Demo.Company.cdCompanyFactory.mdt_sName, "sName", ref value)) this._DBData.sName = value;
        this.TrackChange("sName");
    }
}

// Das Property selbst
[ComponentProperty]
public virtual FSstring sName
{
    get { return this.sNameValue; }
    set { this.sNameValue = value; }
}

// Typneutraler Zugriff für das Databinding
public object sNameAsObject
{
    get { return this.IsDeleted ? null : (object)sName; }
    set { this.sName = FSstring.FromObject(value); }
}

// Der Wert, der aus der Datenbank geladen wurde
public FSstring sNameOrgValue
{
    get { return FS.Demo.Company.cdCompanyFactory.mdt_sName.GetValidValue((this._DBOriginalData ?? this._DBData).sName); }
}

Das zeigt die Aufgabenteilung:

  • sName ist das Property, das Forms, andere Components und Ihr Code verwenden. Getter und Setter reichen nur an sNameValue durch.
  • sNameValue enthält die eigentliche Logik. Der Wert liegt im Datensatz der Query (_DBData), nicht in einem eigenen Feld.
  • sNameOrgValue liefert den Wert, der aus der Datenbank geladen wurde. Daran können Sie erkennen, ob ein Property geändert wurde.
  • sNameAsObject wird vom Databinding verwendet. Bei einer gelöschten Component liefert der Getter null.

Ablauf beim Setzen eines Werts

Die Anweisung oCompany.sName = "Muster GmbH"; durchläuft den Setter von sNameValue:

  1. Hat sich der Wert nicht geändert oder darf das Property gerade nicht gesetzt werden (z. B. bei einer gelöschten Component), passiert nichts.
  2. Der Wert wird über den Metadatentyp mdt_sName geprüft und ggf. angepasst und dann in den Datensatz der Query geschrieben. Ist die Spalte eine ML-Column, wird er als Text der aktuellen Sprache abgelegt.
  3. TrackChange("sName") setzt den Status der Component auf Changed und löst PropertyChanged aus. Dadurch aktualisieren sich z. B. gebundene Controls.

Beim Lesen läuft der Wert ebenfalls über den Metadatentyp, damit z. B. ein Default-Wert greift. Ausnahmen sind die Properties für FSROWID und FSROWVERSION: ROWIDValue liest und schreibt _DBData.ROWID direkt.

Eigenen Code in Getter und Setter schreiben

Mit der Checkbox Write Individual auf der Registerkarte Get Method bzw. Set Method ersetzen Sie den Getter oder Setter von sName. sNameValue bleibt dabei unverändert. Arbeiten Sie deshalb in Ihrem Code mit this.sNameValue, dann bleiben Prüfung und Change-Tracking erhalten:

// Set Method von sName mit Write Individual
// … eigene Logik vor dem Setzen …
this.sNameValue = value;

Wird das Property in einer Customization oder einer abgeleiteten Component angepasst, werden sNameValue, sNameOrgValue und sNameAsObject nicht erneut erzeugt, es gelten die Member der Basis. Das Property sName wird mit override überschrieben. Verwenden Sie in Getter und Setter einer Customization base.sName, damit die Logik des Basis-Packages erhalten bleibt.

Ein Relation-Property

Für das Relation-Property oCountry erzeugt Framework Studio zusätzlich zwei Methoden, die der Getter von oCountryValue aufruft:

protected virtual bool Should_oCountryValueBeLoaded(FS.Demo.Country.cdCountry value)
{
    return value == null || !FSComparer.Equals(this.sCountry, value.sID);
}

protected virtual FS.Demo.Country.cdCountry Load_oCountryValue(FS.Demo.Country.cdCountry _oCountryValue)
{
    // Inhalt der Registerkarte Load Command
    _oCountryValue = new FS.Demo.Country.cdCountry();
    if (!this.sCountry.IsNull)
    {
        string Result = "[sID]" + DB.SqlString("=", this.sCountry);
        var cached = this.GetCachedRelation("oCountry", Result) as FS.Demo.Country.cdCountry;
        if (cached != null)
        { _oCountryValue = cached; }
        else
        {
            if (_oCountryValue.Load(Result) <= 0)
            {
                _oCountryValue.sIDAsObject = this.sCountry;
            }
            this.SetCachedRelation("oCountry", Result, _oCountryValue);
        }
    }
    return _oCountryValue;
}

protected FS.Demo.Country.cdCountry oCountryValue
{
    get
    {
        if (Should_oCountryValueBeLoaded(_oCountryValue ?? (_oCountryValue = new FS.Demo.Country.cdCountry())))
            _oCountryValue = Load_oCountryValue(_oCountryValue);
        return _oCountryValue ?? (_oCountryValue = new FS.Demo.Country.cdCountry());
    }
    set
    {
        if (_oCountryValue == value || !this.CanSetProperty()) return;
        _oCountryValue = value;
        this.FirePropertyChanged("oCountry");
    }
}

[ComponentProperty]
[DependsOnProperties("sCountry")]
public virtual FS.Demo.Country.cdCountry oCountry
{
    get { return this.oCountryValue; }
    set { this.oCountryValue = value; }
}

So funktioniert die Relation:

  • Should_oCountryValueBeLoaded vergleicht die Properties aus Depends On mit der geladenen Instanz. Die Relation wird also erst beim Zugriff geladen und erneut, sobald sCountry nicht mehr zum geladenen Land passt.
  • Load_oCountryValue lädt das Land über eine Load-Condition aus den Angaben unter Depends On. Bereits geladene Relationen mit derselben Load-Condition werden aus einem Cache genommen. Gibt es kein passendes Land, enthält die Instanz nur den Schlüssel aus sCountry.
  • Den Inhalt von Load_oCountryValue erzeugt Framework Studio aus der Relation. Auf der Registerkarte Load Command können Sie ihn durch eigenen Code ersetzen.
  • Beide Methoden sind virtual und können in abgeleiteten Components überschrieben werden.
Warning

Ist auf der Registerkarte Depends On kein Property eingetragen, liefert Should_<Name>ValueBeLoaded immer true. Die Relation wird dann bei jedem Zugriff neu geladen.

Anders als bei einem Generated-Property ändert das Setzen einer Relation den Status der Component nicht. Es wird nur PropertyChanged ausgelöst. Dasselbe gilt für alle Properties einer Collection.

Relation in einen anderen Namespace

cdCountry liegt im Namespace FS.Demo.Country, oCountry verwendet die Klasse cdCountry direkt. Die Assembly von cdCompany referenziert dazu die Assembly FS.Demo.Country_C. Das Interface von cdCompany wird dagegen vor den Components kompiliert (siehe Kompilierreihenfolge) und kennt nur das Interface IcdCountry. Deshalb erzeugt Framework Studio zusätzlich eine explizite Interface-Implementierung:

FS.Demo.Country.IcdCountry FS.Demo.Company.FSDemo_IcdCompany.oCountry
{
    get { return (FS.Demo.Country.IcdCountry)this.oCountry; }
    set { this.oCountry = (FS.Demo.Country.cdCountry)value; }
}

Ist am Property UseInterface gesetzt, ist der Datentyp des Properties selbst das Interface IcdCountry und neue Instanzen werden über cdCountryFactory.Create() erzeugt.

Ein DateTime-Property

Für ein Property vom Typ DateTime entsteht dasselbe Muster wie für sName, zusätzlich das readonly Property <Name>Str:

public string <Name>Str
{
    get { return ConvertDateToDB120DateFormatString(<Name>); }
}

Es liefert den Wert im Format yyyy-MM-dd HH:mm:ss (ODBC canonical, Format-ID 120), z. B. für eigene Load-Conditions.

Die Datensatz-Typen einer DataComponent

Für eine Component mit Query werden im selben Namespace weitere Typen erzeugt. Sie werden vom Framework beim Laden und Speichern verwendet, in eigenem Code brauchen Sie sie selten.

Typ Inhalt
cdCompany_DataStruct (erbt von DataStructBase) Ein Feld pro Spalte der Query. Hält den geladenen Datensatz und ist das _DBData aus den Beispielen oben.
cdCompany_PKStruct (implementiert IPKStruct) Ein Feld pro Primärschlüssel-Property, bei cdCompany nur ROWID. Identifiziert den Datensatz, solange er noch nicht vollständig geladen ist, z. B. in einer Collection jenseits der Load Size. Für neue, noch nicht gespeicherte Datensätze wird eine temporäre ID vergeben.
cdCompany.QueryInfoClass (erbt von FrameworkQueryInfo) Das SELECT-Statement der Query sowie die Informationen zum Sortieren und Filtern.
