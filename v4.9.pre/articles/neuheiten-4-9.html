Neuheiten Framework Studio 4.9

Informationen zu aktuellen Versionen und korrigierten Fehlern finden Sie in den Release-Informationen.

Important

Dieses Dokument zeigt die Neuerungen beim Update von Version 4.8 auf 4.9. Beim Update von einer älteren Version beachten Sie bitte auch die Hinweise und Neuerungen der älteren Version (Neuheiten 4.8).

Update DLLs

Mit Framework Studio 4.9 wurden die Versionen aller referenzierten Pakete aktualisiert.

Dadurch kann es beim Compile eigener Anwendungen zu neuen Errors oder Warnings kommen, wenn eingebundene Ressourcen (DLLs) nicht mehr zu den aktualisierten Versionen passen. Details zur Ursache und zur Behebung solcher Meldungen finden Sie unter Referenz-Prüfung für Ressourcen.

Eine Übersicht der wichtigsten aktualisierten Bibliotheken und der neu ausgelieferten DLLs finden Sie in den Release-Informationen.

Roslyn-Compiler

Der mitgelieferte Roslyn-Compiler, mit dem Framework Studio die Anwendungen compiliert, wurde auf Version 4.14 aktualisiert.

Datenbank-Abgleich unter SQL Server

Die Differenzlogik für SQL Server wurde in mehreren Punkten verbessert. Details finden Sie in den Release-Informationen.

  • Binärspalten werden nicht mehr mit dem seit 2006 veralteten Datentyp image, sondern als varbinary(max) angelegt. Bestehende image-Spalten werden im Modus DBDifferenceAnalyzeMode.Cleanup erkannt und zur Konvertierung angeboten.
  • FSROWID-Spalten werden korrekt als uniqueidentifier erwartet.
  • Spalten vom Typ datetime2 werden im Cleanup-Modus gemeldet und sollten zu datetime konvertiert werden.
  • Abweichungen bei Boolean (bit), Byte (tinyint), Guid (uniqueidentifier) und Gleitkommazahlen (float/real) werden nun erkannt.
  • Verwaiste Tabellen und Spalten, die in der Datenbank existieren, aber in Framework Studio nicht (mehr) definiert sind, werden im Cleanup-Modus gemeldet. Für sie wird bewusst kein DROP-Skript erzeugt.
Warning

Mit DBDifferenceAnalyzeMode.Cleanup erzeugte SQL-Skripte sollten niemals automatisch ausgeführt werden. Indizes, die nur in der Datenbank, nicht aber in Framework Studio definiert sind, werden dabei tatsächlich gelöscht.

Authentication Service

Anmeldung per JWT

Der Authentication Service kann nun ein von einem registrierten OpenID-Connect-Identity-Provider ausgestelltes Token (JWT) direkt verarbeiten und den zugehörigen Benutzer identifizieren. Damit können sich z.B. externe Clients, die bereits beim Identity Provider angemeldet sind, mit ihrem Token an Framework Studio Anwendungen authentifizieren.

Trägt das durchgereichte Token eine andere Audience als die ClientID des Authentication Service, können im neuen Feld Additional Valid Audiences weitere gültige Audiences hinterlegt werden.

Configuration Editor überarbeitet

Die Oberfläche des Authentication Service Configuration Editors wurde überarbeitet. Die Felder für die OpenID Connect Authentication sind nun ausführlich dokumentiert.

MCP-Server (Beta)

Framework Studio enthält einen MCP-Server, über den KI-Assistenten wie Claude Code oder GitHub Copilot in Visual Studio Code lesend auf das Repository der laufenden IDE zugreifen. Er implementiert das Model Context Protocol (MCP) und wird über Tools / MCP-Server starten (Beta) gestartet.

Über die Tools des Servers können KI-Assistenten Elemente auflisten und lesen, im Code und in der Element-Dokumentation suchen und die Änderungshistorie abfragen. Zusätzlich enthält der Server die Framework Studio-Hilfe und die API-Referenz passend zur installierten Version.

Important

Der MCP-Server ist als Beta-Feature enthalten. Funktionsumfang und Schnittstellen können sich in zukünftigen Versionen ändern.

Weitere Neuerungen

  • SQLite-Datenbanken (z.B. bei Publish2Go) können nun auch über einen UNC-Pfad geöffnet werden.
