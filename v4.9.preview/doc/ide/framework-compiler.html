FrameworkCompiler

Der FrameworkCompiler ist ein besonderer Benutzer innerhalb von Framework Studio. Seine Hauptaufgabe besteht darin, den kompilierten Code einer Anwendung, den sog. Saved-Code, in das Repository zu schreiben.

Hintergrund ist das Entwicklungsmodell von Framework Studio. Mehrere Entwickler arbeiten an einer Anwendung, checken Elemente aus und ein. Der FrameworkCompiler ist die Instanz, die alle Änderungen zu einem gesamten funktionierenden Stand zusammenfügt. Dies könnte z.B. nachts über einen Job stattfinden, da zu dieser Zeit normalerweise auch kein Entwickler angemeldet ist.

Warning

Der FrameworkCompiler kann selbst keine Objekte auschecken und bearbeiten. Siehe hierzu Benutzer bearbeiten.

Ein Compile-Vorgang mit dem FrameworkCompiler hat folgenden Ablauf:

  • Als erstes wird der Workspace des FrameworkCompiler aktualisiert. Hier werden alle von den Entwicklern eingecheckten Objekte herangezogen.
  • Danach wird der gesamte Code kompiliert. Der Quellcode (Saved Code) sowie die daraus erzeugten Assemblies werden nach einem erfolgreichen Compile-Vorgang in die Datenbank geschrieben.
  • Nun wird der Compile-Stamp des FrameworkCompilers aktualisiert. Hieran wird festgesetzt, ob die Entwickler mit einem aktuellen Workspace arbeiten oder nicht.

Ein erfolgreicher Durchlauf des FrameworkCompilers stellt somit sicher, dass sich im Repository ein sauberer Entwicklungsstand mit jeglichem Source Code und jeglichen Assemblies befindet, auf dem die Entwickler ihre tägliche Arbeit aufbauen können.

Kompilierreihenfolge

Innerhalb einer Packageversion werden die Elemente nach ihrem Typ in festen Stufen kompiliert. Die meisten Stufen erzeugen pro Namespace eine eigene Assembly. Deren Name setzt sich aus dem Namespace und einer Endung zusammen, z. B. Sales_C für die Components des Namespaces Sales. Access Unit Owner, Interfaces und Workflows werden dagegen namespace-übergreifend in jeweils eine Assembly kompiliert.

Stufe Elementtyp Endung der Assembly
1 Resources _R
2 Access Unit Owner _AUO
3 Metadatentypen _MDT
4 DB-Tabellen _DBT
5 Interfaces _I
6 Report Document Types _RDT
7 Services _Svc
8 REST Services _RestSvc
9 Components _C
10 GlobalObjects _GO
11 Unit-Tests _UT
12 Custom Controls _CC
13 Forms _Frm
14 Workflows _Wfl

Eine Stufe greift auf die Assemblies der Stufen zu, die vor ihr kompiliert wurden. Innerhalb einer Stufe kann eine Assembly die Assemblies anderer Namespaces referenzieren, z. B. FS.Demo.Company_C die Assembly FS.Demo.Country_C. Zwei Namespaces können sich aber nicht gegenseitig referenzieren. Für solche Fälle gibt es UseInterface: Das Property verwendet dann das Interface aus Stufe 5. Beim Anlegen eines Properties, dessen Datentyp eine Component aus einem anderen Namespace ist, schlägt Framework Studio UseInterface vor.

Daraus folgt für die tägliche Arbeit:

  • Ein Fehler in einer frühen Stufe kann Folgefehler in allen späteren Stufen auslösen. Beheben Sie Kompilierfehler deshalb von der frühesten Stufe an.
  • Betrifft eine Änderung mehrere Elemente, bauen Sie sie in dieser Reihenfolge auf. Für ein neues Feld in der Datenbank ändern Sie zuerst die DB-Tabelle, dann die Component und zuletzt das Form.
